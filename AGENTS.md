# AGENTS.md — инструкция для работы над проектом TODOCITY

Этот файл читается автоматически в начале каждой сессии. Здесь зафиксированы договорённости,
архитектура и правила. **При смене договорённостей — обновлять этот файл.**

## Что за проект

TODOCITY — локальное веб-приложение для ведения списков дел. Чистый статический фронтенд
без сборки и фреймворков: `index.html` + `style.css` + `main.js` + векторный логотип
`logo-todocity.svg` (вектор из CorelDRAW, имя файла без пробелов). Данные — в localStorage
браузера (ключ `todo-app-v47`), серверной части пока нет. Облачный деплой и git отложены.

## Правила разработки (критично)

1. **Версионирование ресурсов.** При ЛЮБОЙ правке `style.css` или `main.js` поднять версию
   в ссылках `index.html`: `style.css?v=N`, `main.js?v=N`. Иначе браузер (в т.ч. встроенный
   IAB) отдаёт кешированную старую версию. Текущие версии: **style.css?v=15, main.js?v=12**.
2. **Формат дат.** Хранить даты только как локальную полночь: хелпер `localMidnightISO(d)`.
   Никогда не использовать `toISOString().split('T')[0]` — это UTC, даёт смещение на день
   в таймзонах восточнее UTC. Для полей `<input type="date">` — хелпер `toLocalISODate(d)`.
3. **Локальный сервер.** `python -m http.server 8127` из папки проекта (фоновый процесс
   имеет свойство умирать — при пустой странице перезапустить). Адрес: http://localhost:8127.
   Исторически порт меняли (8123→8127) из-за кеша браузера; с версионированием порт стабилен.
4. **Проверки в автоматике.** HTML5 drag-and-drop НЕ эмулируется автоматизированным вводом —
   драг-сценарии проверяются руками пользователем. Прямое чтение стилей через evaluate
   нестабильно — проверять классами/локаторами/скриншотами.
5. **localStorage привязан к origin** (порт = другой origin). Смена порта/домена = новые данные.
6. **Синтаксис после правок** проверять `node --check main.js`.

## Архитектура (кратко)

- Состояние: глобальный `state` (tasks, groups, tags, systemListsConfig, listVisibility,
  activeGroupId, dealOfDayId, filter, form*, activeTimer, sidebarCollapsed, theme…),
  сохраняется целиком в localStorage; флаг `seeded` не даёт демо-данным вернуться после удаления.
- Модель задачи: `{ id, text, note, dueDate (локальная полночь, ISO), endDate, startTime ("ЧЧ:ММ"
  | null), endTime ("ЧЧ:ММ" | null), importance, groupId, tags[], done, subtasks[], createdAt,
  repeat ({type: daily|weekly|monthly, days[]}|null), timerDuration }`.
- Календарь задач: `isTaskOnDay(t, day)` — учитывает повторы (daily/weekly/monthly) и endDate;
  используется списками «Сегодня»/«Завтра», счётчиками и таймлайном единообразно.
- «Дело дня» (звезда) автоматически ставит задаче сегодняшнюю дату. Драг задачи на «Выполнено»
  завершает её; на «Запланировано»/«Все»/«Просрочено» дроп запрещён.
- Таймлайн (правая выезжающая панель): 48 получасовых строк, линия текущего времени (обновляется
  раз в 30с при открытой панели), задачи со временем кладутся чипами в строку снапом
  `timeToRow()` (14:20 → строка 14:00, на чипе точное время). Драг задачи/чипа в строку задаёт
  дату+время; дроп в блок «без времени» снимает время. Задача со временем, но без даты —
  считается сегодняшней (и в форме, и в редакторе).
- Открытие таймлайна вешает `body.timeline-open`: контент сдвигается (`margin-right`), а не
  перекрывается; на ширине ≤960px — перекрытие без сдвига.
- Редактор задачи: Enter — сохранить, Esc — отмена из любого поля (в textarea Enter — перенос).
- Валидации: дата завершения ≥ даты начала; время окончания > времени начала (тост об ошибке).
- Темы: dark/light через `body[data-theme]`; бренд-логотип — единый SVG-файл на обе темы.

## Окружение

Windows, папка проекта в OneDrive (синхронизация может запаздывать на других устройствах).
Шрифты Google Fonts (Unbounded, Manrope) и Font Awesome 6.4 — с CDN, нужен интернет.
Демо-данные засеиваются только при первом запуске на чистом origin.
