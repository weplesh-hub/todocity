# AGENTS.md — инструкция для работы над проектом TODOCITY

Этот файл читается автоматически в начале каждой сессии. Здесь зафиксированы договорённости,
архитектура и правила. **При смене договорённостей — обновлять этот файл.**

## Что за проект

TODOCITY — веб-приложение для ведения списков дел. Чистый статический фронтенд
без сборки и фреймворков: `index.html` + `style.css` + `main.js` + векторный логотип
`logo-todocity.svg` (вектор из CorelDRAW, имя файла без пробелов). **В подпапке `calcalk/`
живёт второе приложение — КалКалк (трекер калорий и воды, тоже чистая статика:
index.html + styles.css + app.js, localStorage `calcalk_v1`)**. Иконки в КалКалке —
только монохромные линейные SVG (словарь ICONS + `icoWrap()` в app.js; в статике —
`<span class="ic" data-ico="…">`), эмодзи в UI не использовать; «Приём пищи» —
сегментный переключатель buildMealPicker (SVG в нативном select невозможен),
скрытые инпуты #foodMeal/#qdMeal сохраняют `.value`-API. Приложения объединены:
кнопка 🍴 в ряду кнопок даты TODOCITY → `calcalk/`, кнопка 📋 в шапке КалКалка → `../`;
единый аккаунт (общий origin = общий localStorage: КалКалк показывает логин из
`todo-app-v47-login` в своих настройках). Данные TODOCITY — в localStorage
браузера (ключ `todo-app-v47`); при входе в аккаунт — синхронизация с бэкендом VPS
(см. раздел «Бэкенд и синхронизация»). Данные КалКалка пока только локальные
(экспорт/импорт JSON в его настройках). Репозиторий и публикации: GitHub Pages + VPS
(оба приложения деплоятся вместе, / и /calcalk/).

## Правила разработки (критично)

1. **Версионирование ресурсов.** При ЛЮБОЙ правке `style.css` или `main.js` поднять версию
   в ссылках `index.html`: `style.css?v=N`, `main.js?v=N`. Иначе браузер (в т.ч. встроенный
   IAB) отдаёт кешированную старую версию. Текущие версии (сверено 07.10.2026): **style.css?v=43,
   main.js?v=45**; calcalk: styles.css?v=46, app.js?v=25.
2. **Формат дат.** Хранить даты только как локальную полночь: хелпер `localMidnightISO(d)`.
   Никогда не использовать `toISOString().split('T')[0]` — это UTC, даёт смещение на день
   в таймзонах восточнее UTC. Для полей `<input type="date">` — хелпер `toLocalISODate(d)`.
3. **Локальный сервер.** `python -m http.server 8127` из папки проекта (фоновый процесс
   имеет свойство умирать — при пустой странице перезапустить). Адрес: http://localhost:8127.
   Исторически порт меняли (8123→8127) из-за кеша браузера; с версионированием порт стабилен.
4. **Проверки в автоматике.** HTML5 drag-and-drop НЕ эмулируется автоматизированным вводом —
   драг-сценарии проверяются руками пользователем. Прямое чтение стилей через evaluate
   нестабильно — проверять классами/локаторами/скриншотами.
5. **localStorage привязан к origin** (порт = другой origin). Смена порта/домена = новые данные.
6. **Синтаксис после правок** проверять `node --check main.js`.

## Бэкенд и синхронизация (с 30.08.2026)

- `server.py` — бэкенд на чистом stdlib (http.server + sqlite3), развёрнут на VPS:
  /srv/todocity-backend, systemd-сервис `todocity-backend`, слушает 127.0.0.1:8080,
  nginx проксирует `/api/` наружу. База: /srv/todocity-backend/data.db.
- API: POST /api/register|login|logout|password, GET/PUT /api/state, GET /api/ping.
  Пароли PBKDF2, токены Bearer 30 дней. POST /api/password (Bearer, {old,new}) — смена пароля;
  неверный старый → 403 (НЕ 401 — иначе фронт роняет сессию), сессии при смене сохраняются.
  Кнопка «Сменить пароль» — в настройках аккаунта (диалог showPasswordDialog, main.js). CORS-allowlist: localhost/127.0.0.1, VPS-адрес,
  weplesh-hub.github.io (обновляется в ORIGIN_RE и в API_BASE в main.js).
- Фронтенд: раздел «Аккаунт и синхронизация» в настройках. Автопуш через 1.2с после
  saveState (флаг `syncing` защищает от цикла), автозагрузка при старте — только если
  сервер новее локальной метки `todo-app-v47-synced-at` (офлайн-правки не затираются).
  Токен: `todo-app-v47-token`, логин: `todo-app-v47-login`.
- **Сессии мульти-устройственные** (таблица `sessions`, 30 дней со скользящим продлением):
  вход на новом устройстве НЕ выкидывает уже вошедшие; logout закрывает только текущую сессию.
- **Слоты состояний по приложениям**: таблица `states` — PK (user_id, app), app ∈ {todo, calcalk}.
  API: `/api/state?app=todo|calcalk` (без параметра = todo — обратная совместимость).
  TODOCITY шлёт своё состояние в слот todo, КалКалк — в calcalk; обновления независимы.
- **Синхронизация КалКалка** (calcalk/app.js, cc*-функции): тот же токен из
  `todo-app-v47-token` (общий origin), автопуш через 1.2с после saveState, стартовый
  pull-или-push по метке `calcalk-synced-at`, кнопка «Синхронизировать» и статус в карточке
  аккаунта его настроек. Выход из TODOCITY вычищает и `calcalk_v1` с меткой.
- **База продуктов КалКалка** (вкладка «Продукты»): просмотр с поиском, правка базовых
  (settings.dbOver {имя: КБЖУ}, бейдж «изменён», «Сбросить правку»), свои продукты
  (settings.dbCustom, бейдж «свой»). «Удалить» в карточке — безвозвратно: свои удаляются,
  базовые уходят в settings.dbHidden навсегда (БЕЗ восстановления — блок «Вернуть» убран).
  В карточке также «Очистить» (стереть поля). Эффективная база getFoodDB() = FOOD_DB
  с правками минус скрытые + свои; подсказки в форме едят её же. Всё синхронизируется.
- **Выход очищает локальные данные аккаунта** (todo-app-v47, synced-at) — без авторизации
  задачи аккаунта на устройстве не остаются; страница перезагружается в чистое демо-состояние.
  При истечении сессии (401) локальные данные сохраняются (защита офлайн-правок).
- Кнопка синхронизации в верхней панели (⟳ fa-arrows-rotate, `#syncNowBtn`): вошли —
  `doSyncNow()` с вращением иконки (fa-spin); не вошли — тост + открытие настроек.
  Не залогиненным кнопка полупрозрачна (класс `logged-out`). В настройках — имя аккаунта
  и одна кнопка «Синхронизировать» (сервер новее → pull, иначе push). Кнопки настроек
  и синхронизации живут в блоке даты шапки (ряд из 4: календарь, таймлайн, настройки,
  синхронизация), НЕ в top-controls (там только «Свернуть панель»).
- Обновление бэкенда на VPS: pscp server.py → /srv/todocity-backend/ + `systemctl restart
  todocity-backend`. Локальный прогон: `PORT=8128 python server.py` (data.db игнорируется).
- Известное ограничение: HTTP без TLS (пароль идёт открыто) — до домена и certbot.

## Архитектура (кратко)

- Состояние: глобальный `state` (tasks, groups, tags, systemListsConfig, listVisibility,
  activeGroupId, dealOfDayId, filter, form*, activeTimer, sidebarCollapsed, theme…),
  сохраняется целиком в localStorage; флаг `seeded` не даёт демо-данным вернуться после удаления.
- Модель задачи: `{ id, text, note, dueDate (локальная полночь, ISO), endDate, startTime ("ЧЧ:ММ"
  | null), endTime ("ЧЧ:ММ" | null), importance, groupId, tags[], done, subtasks[], createdAt,
  repeat ({type: daily|weekly|monthly, days[]}|null), timerDuration, progressEnabled, progress,
  progressStep, subtasksCollapsed }`. Подзадачи сворачиваются кнопкой «Подзадачи · X/Y»
  над списком (поле subtasksCollapsed, синхронизируется; добавление подзадачи раскрывает список).
- Календарь задач: `isTaskOnDay(t, day)` — учитывает повторы (daily/weekly/monthly) и endDate;
  используется списками «Сегодня»/«Завтра», счётчиками и таймлайном единообразно.
- Кольцо прогресса «Готово» в шапке — процент по задачам **текущего дня** (состав как в списке
  «Сегодня», через isTaskOnDay): выполненная задача считается одной готовой единицей целиком,
  у невыполненной учитываются подзадачи. Пустой день → 0%.
- «Дело дня» (звезда) автоматически ставит задаче сегодняшнюю дату. Драг задачи на «Выполнено»
  завершает её; на «Запланировано»/«Все»/«Просрочено» дроп запрещён.
- **Порядок общего списка**: дело дня → разрыв «Повторяющиеся» → повторы (по умолчанию
  сначала со шкалой прогресса, затем без неё) → разрыв «Остальные дела» → остальные
  (в обоих фильтрах, независимо от автоформатирования). Полоса прогресса —
  ТОЛЬКО ручная шкала повторяющихся дел (progressEnabled); у дела дня и дел с подзадачами
  полосы не показываются (старый прогресс по подзадачам убран вместе с getTaskProgress).
- **Ручная шкала прогресса для повторяющихся дел**: поля задачи `progressEnabled`/`progress`/
  `progressStep` (шаг 1/5/10/25%). Включается тумблером в редакторе вместе с выбором шага
  (видны только при заданном повторе; снятие повтора выключает шкалу). В карточке — слайдер
  0–100 + процент; input обновляет число, change сохраняет (автосинк). Ручка слайдера — цвета
  дела (--task-color), без обводки. Прогресс СОХРАНЯЕТСЯ между повторами (не сбрасывается).
  При установке 100% — диалог «Завершаем дело или изменяем значение в шкале выполнения?»
  (showProgressCompleteDialog): «Завершить дело» → toggleDone (перенос), «Изменить значение»/
  закрытие → остаёмся на 100%. Перетаскивание ползунка не тянет карточку (guard в dragstart).
- **Автоформатирование списка дел на день** (настройки, тумблер `autoFormatDay`, выкл по
  умолчанию, синхронизируется): дело дня → повторяющиеся (repeat) → остальные по приоритету
  (high→medium→low) → без приоритета в конце. Применяется в renderTasks к активным задачам
  любого списка (кроме «Запланировано»/«Выполнено» с группировкой по датам).
- **Тематические папки в списке дел** (main.js v43): кнопка «+папка» (fa-folder-plus) в плашке
  фильтров после кнопки e-mail. **У каждого списка свои папки** (folder.listId = activeGroupId
  при создании; показываются только в своём списке; нумерация «Папка N» — внутри списка;
  старые папки без listId мигрируют в «Сегодня»). В «Запланировано»/«Просрочено»/«Выполнено»
  создание папок отключено (там папки не рендерятся). state.folders [{id,name,collapsed,listId}]
  (синхронизируются), поле задачи folderId. Новая папка = пунктирная строка-цель под списком;
  дроп на заголовок папки/пустую строку переносит дело внутрь; дроп на дело-цель — в её папку.
  Внутри папки тот же порядок (taskGroupHTML: дело дня → повторы со шкалой → остальные).
  Действия на ховере: переименовать (инлайн, Enter/Esc), разгруппировать (дела в корень),
  удалить (диалог: «Только папку» / «Удалить с делами»).
- Таймлайн (правая выезжающая панель): 48 получасовых строк, линия текущего времени (обновляется
  раз в 30с при открытой панели), задачи со временем кладутся чипами в строку снапом
  `timeToRow()` (14:20 → строка 14:00, на чипе точное время). Драг задачи/чипа в строку задаёт
  дату+время; дроп в блок «без времени» снимает время. Задача со временем, но без даты —
  считается сегодняшней (и в форме, и в редакторе).
- **Смена даты дела**: кнопка с календарём (fa-calendar-plus) в ряду функциональных кнопок
  карточки (видна при наведении). Поповер `.date-pick-pop` (fixed, у кнопки, вне карточки —
  карточка имеет overflow:hidden): кнопки Сегодня/Завтра/Послезавтра/Следующий понедельник +
  мини-календарь месяца с листанием (переиспользуются cal-* классы). Выбор ставит dueDate
  (локальная полночь), снимает «дело дня», если дата ушла с сегодня. Закрытие: выбор,
  клик мимо, Esc, скролл.
- Открытие таймлайна вешает `body.timeline-open`: контент сдвигается (`margin-right`), а не
  перекрывается; на ширине ≤960px — перекрытие без сдвига.
- Редактор задачи: Enter — сохранить, Esc — отмена из любого поля (в textarea Enter — перенос).
- Валидации: дата завершения ≥ даты начала; время окончания > времени начала (тост об ошибке).
- Темы: dark/light через `body[data-theme]`; бренд-логотип — единый SVG-файл на обе темы.
